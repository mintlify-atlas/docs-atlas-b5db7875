## GET /api/data/{filename}

Retrieve paginated timeline data with filtering, sorting, and time range queries. Uses **lazy evaluation** for out-of-core processing.

### Path Parameters

<ParamField path="filename" type="string" required>
  CSV filename returned from `/upload` endpoint (e.g., `Security_evtx_1704067200.csv`)
</ParamField>

### Query Parameters

<ParamField query="page" type="integer" default="1">
  Page number (1-indexed)
</ParamField>

<ParamField query="size" type="integer" default="50">
  Records per page (max: 1000)
</ParamField>

<ParamField query="query" type="string">
  Global search query (case-insensitive, searches all columns)
</ParamField>

<ParamField query="start_time" type="string" format="ISO 8601">
  Filter events after this timestamp (inclusive)
</ParamField>

<ParamField query="end_time" type="string" format="ISO 8601">
  Filter events before this timestamp (inclusive)
</ParamField>

<ParamField query="col_filters" type="string" format="JSON">
  Column-specific filters (e.g., `{"EventID":"4624","User":"admin"}`)
</ParamField>

<ParamField query="sort_col" type="string">
  Column name to sort by (alternative: `sort[0][field]` for Tabulator.js compatibility)
</ParamField>

<ParamField query="sort_dir" type="string" enum="asc,desc">
  Sort direction (alternative: `sort[0][dir]`)
</ParamField>

### Response Schema

<ResponseField name="current_page" type="integer">
  Current page number
</ResponseField>

<ResponseField name="last_page" type="integer">
  Total number of pages
</ResponseField>

<ResponseField name="total" type="integer">
  Total records matching filters
</ResponseField>

<ResponseField name="total_unfiltered" type="integer">
  Total records in file (before filters)
</ResponseField>

<ResponseField name="data" type="array">
  Array of timeline events (objects with dynamic schema)
</ResponseField>

<ResponseField name="start_time" type="string" nullable>
  Earliest timestamp in filtered dataset
</ResponseField>

<ResponseField name="end_time" type="string" nullable>
  Latest timestamp in filtered dataset
</ResponseField>

### Examples

<CodeGroup>

```bash Basic Query
curl "http://localhost:8000/api/data/Security_evtx_1704067200.csv?page=1&size=50"
```

```bash Search Query
curl "http://localhost:8000/api/data/Security_evtx_1704067200.csv?query=powershell"
```

```bash Time Range Filter
curl "http://localhost:8000/api/data/Security_evtx_1704067200.csv?start_time=2024-01-01T00:00:00&end_time=2024-01-02T00:00:00"
```

```bash Column Filter + Sort
curl "http://localhost:8000/api/data/Security_evtx_1704067200.csv?col_filters={\"EventID\":\"4624\"}&sort_col=Time&sort_dir=desc"
```

```python Python Client
import requests

response = requests.get(
    "http://localhost:8000/api/data/Security_evtx_1704067200.csv",
    params={
        "page": 1,
        "size": 100,
        "query": "admin",
        "start_time": "2024-01-01T00:00:00",
        "col_filters": '{"EventID":"4624"}'
    }
)

data = response.json()
print(f"Total matches: {data['total']}")
for event in data['data']:
    print(f"{event['Time']} - {event['EventID']}")
```

</CodeGroup>

## GET /api/histogram/{filename}

Generate time-series histogram with event distribution, peaks, and outlier detection.

### Path Parameters

<ParamField path="filename" type="string" required>
  CSV filename from upload
</ParamField>

### Query Parameters

<ParamField query="exclude_id" type="string">
  EventID to exclude from histogram (e.g., `4624` for logon noise reduction)
</ParamField>

<ParamField query="start_time" type="string" format="ISO 8601">
  Time range start
</ParamField>

<ParamField query="end_time" type="string" format="ISO 8601">
  Time range end
</ParamField>

<ParamField query="query" type="string">
  Global search filter
</ParamField>

<ParamField query="col_filters" type="string" format="JSON">
  Column-specific filters
</ParamField>

<ParamField query="selected_ids" type="string" format="JSON">
  Row IDs for subset histogram (e.g., `["5","20","100"]`)
</ParamField>

### Response Schema

<ResponseField name="labels" type="array<string>">
  X-axis labels (timestamps or time buckets)
</ResponseField>

<ResponseField name="datasets" type="array<object>">
  Chart.js dataset objects with event counts per bucket
</ResponseField>

<ResponseField name="stats" type="object">
  Statistical summary
  
  <ResponseField name="peak" type="integer">
    Maximum events in a single bucket
  </ResponseField>
  
  <ResponseField name="mean" type="float">
    Average events per bucket
  </ResponseField>
  
  <ResponseField name="start_time" type="string">
    Dataset start timestamp
  </ResponseField>
  
  <ResponseField name="end_time" type="string">
    Dataset end timestamp
  </ResponseField>
</ResponseField>

<ResponseField name="interpretation" type="string">
  Human-readable summary (e.g., "High activity spike detected at 2024-01-01 14:00")
</ResponseField>

### Example

```bash
curl "http://localhost:8000/api/histogram/Security_evtx_1704067200.csv?exclude_id=4624"
```

## POST /api/forensic_report

Generate comprehensive forensic analysis with **parallel execution** of:

- Timeline analysis (peaks, gaps, anomalies)
- Context extraction (users, IPs, processes)
- Threat hunting (suspicious patterns)
- Sigma rule matching (86 rules)
- YARA scanning
- MITRE ATT&CK mapping
- Cross-source correlation
- Session profiling
- Risk scoring (Smart Risk Engine M4)
- Threat intelligence enrichment

### Request Body

<ParamField body="filename" type="string" required>
  CSV filename to analyze
</ParamField>

<ParamField body="query" type="string" optional>
  Global search filter
</ParamField>

<ParamField body="col_filters" type="object" optional>
  Column-specific filters
</ParamField>

<ParamField body="selected_ids" type="array<string>" optional>
  Row IDs for subset analysis
</ParamField>

<ParamField body="start_time" type="string" optional>
  Time range start
</ParamField>

<ParamField body="end_time" type="string" optional>
  Time range end
</ParamField>

<ParamField body="sort_col" type="string" optional>
  Sort column
</ParamField>

<ParamField body="sort_dir" type="string" optional>
  Sort direction
</ParamField>

### Response Schema

<ResponseField name="total_records" type="integer">
  Number of events analyzed
</ResponseField>

<ResponseField name="filename" type="string">
  Source filename
</ResponseField>

<ResponseField name="top_tactic" type="string">
  Most common tactic/event type (e.g., "Win EventID 4688: Process Creation")
</ResponseField>

<ResponseField name="primary_identity" type="string">
  Most active user/IP
</ResponseField>

<ResponseField name="risk_level" type="string" enum="Critical,High,Medium,Low">
  Overall risk assessment
</ResponseField>

<ResponseField name="risk_score" type="integer" range="0-100">
  Numeric risk score
</ResponseField>

<ResponseField name="risk_justify" type="array<string>">
  Risk justification factors (e.g., ["Sigma critical hit: Mimikatz detected", "Lateral movement detected"])
</ResponseField>

<ResponseField name="eps" type="float">
  Events per second (activity rate)
</ResponseField>

<ResponseField name="results" type="array<object>">
  Analysis results from 4 parallel tasks:
  
  - **Timeline**: Peaks, gaps, time range
  - **Context**: Users, IPs, hosts, paths, event IDs
  - **Hunting**: Suspicious patterns, network connections, logon events
  - **Identity**: Top processes, rare executions, asset inventory
</ResponseField>

<ResponseField name="sigma_hits" type="array<object>">
  Matched Sigma rules with evidence rows
  
  <ResponseField name="title" type="string">
    Rule name
  </ResponseField>
  
  <ResponseField name="level" type="string" enum="critical,high,medium,low">
    Severity level
  </ResponseField>
  
  <ResponseField name="mitre_technique" type="string">
    MITRE ATT&CK technique ID (e.g., "T1059.001")
  </ResponseField>
  
  <ResponseField name="matched_rows" type="integer">
    Total matching events
  </ResponseField>
  
  <ResponseField name="sample_evidence" type="array<object>">
    First 150 matching rows with forensic context columns
  </ResponseField>
  
  <ResponseField name="all_row_ids" type="array<integer>">
    All matching row IDs (up to 500)
  </ResponseField>
</ResponseField>

<ResponseField name="yara_hits" type="array<object>">
  YARA rule matches (scans first 5MB of CSV text)
</ResponseField>

<ResponseField name="mitre_kill_chain" type="array<object>">
  MITRE ATT&CK tactics derived from Sigma hits
</ResponseField>

<ResponseField name="cross_source_correlation" type="object">
  Cross-file correlation chains (user, IP, process pivots)
</ResponseField>

<ResponseField name="session_profiles" type="array<object>">
  Session behavior profiles (dwell time, request patterns)
</ResponseField>

<ResponseField name="execution_artifacts" type="object">
  Detected execution artifacts (Prefetch, ShimCache, AmCache)
</ResponseField>

<ResponseField name="threat_intelligence" type="object">
  IOC enrichment from threat feeds (VirusTotal, AbuseIPDB, etc.)
</ResponseField>

### Example

<CodeGroup>

```bash Full Report
curl -X POST http://localhost:8000/api/forensic_report \
  -H "Content-Type: application/json" \
  -d '{
    "filename": "Security_evtx_1704067200.csv"
  }'
```

```bash Filtered Report
curl -X POST http://localhost:8000/api/forensic_report \
  -H "Content-Type: application/json" \
  -d '{
    "filename": "Security_evtx_1704067200.csv",
    "col_filters": {"User": "admin"},
    "start_time": "2024-01-01T00:00:00"
  }'
```

```python Python Client
import requests

response = requests.post(
    "http://localhost:8000/api/forensic_report",
    json={
        "filename": "Security_evtx_1704067200.csv",
        "col_filters": {"EventID": "4688"},
        "query": "powershell"
    }
)

report = response.json()
print(f"Risk: {report['risk_level']} ({report['risk_score']}/100)")
print(f"Sigma hits: {len(report['sigma_hits'])}")
for hit in report['sigma_hits']:
    print(f"  - {hit['title']} ({hit['level']})")
```

</CodeGroup>

### Performance

Report generation uses **parallel execution** with `asyncio.gather()` (9 concurrent tasks):

- Timeline analysis: ~0.8s
- Context extraction: ~1.2s
- Hunting patterns: ~1.5s
- Identity analysis: ~1.0s
- Sigma matching: ~2.5s
- YARA scan: ~0.5s
- Correlation: ~1.8s
- Sessions: ~1.2s
- Execution artifacts: ~0.9s
- **Total**: ~3.5s (wall-clock time, 9 tasks in parallel)

*Tested on 42,084 EVTX events*

<Note>
  Threat intelligence enrichment adds 5-30s depending on API rate limits.
</Note>

## POST /api/histogram_subset

### Request Body

<ParamField body="filename" type="string" required>
  CSV filename
</ParamField>

<ParamField body="selected_ids" type="array<string>" required>
  Row IDs to include (e.g., `["5", "20", "100"]`)
</ParamField>

<ParamField body="query" type="string" optional>
  Global search filter
</ParamField>

<ParamField body="col_filters" type="object" optional>
  Column filters
</ParamField>

<ParamField body="start_time" type="string" optional>
  Time range start
</ParamField>

<ParamField body="end_time" type="string" optional>
  Time range end
</ParamField>

### Response

Same schema as `/api/histogram/{filename}` with `interpretation` prefixed by `"Filtered View: "`.

## GET /api/empty_columns/{filename}

Identify completely empty columns (all nulls or empty strings) for UI optimization.

### Query Parameters

Same filtering params as `/api/data/{filename}` (query, col_filters, start_time, end_time, selected_ids).

### Response

```json
{
  "empty_columns": ["Field5", "Hashes", "ParentImage"]
}
```

<Note>
  Excludes internal columns (`_id`, `No.`, `Original_No.`) from empty check.
</Note>
